## 维护窗口：发现的产品缺陷与修复（PR #249）

维护程序 GUI 此前从未走过第一步。修好测试助手后，柜台“刷新备份状态”和“打开维护程序”均正常，维护窗口完整显示（截图确认 22 个按钮、输出区已读到备份状态）。
随后旅程按设计先关闭柜台，再在维护窗口操作，此时维护进程已不存在。

根因：Windows 上 Node 把柜台 `spawn` 的子进程放进“父进程退出即结束全部成员”的作业，维护窗口原本运行在该子进程（引导脚本）里。
winbox 探针：普通子进程在父进程退出 3 秒内被结束；`detached: true` 启动的 PowerShell 不执行；子进程再启动的孙进程会保留。
门店照“请先退出柜台”操作时，维护窗口会随柜台消失。

| 版本              | 做法                                                              | 实测                                                                          |
| ----------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| pilot4 `49d99c36` | 引导脚本用重定向的 `Process.Start` 起窗口进程                     | 编码命令 34580 字符，超过 32767 上限，柜台起不来维护进程，备份状态读取失败    |
| pilot5 `28ddd04a` | 同上，压缩到 31984 字符                                           | 维护窗口在柜台退出后保留；但窗口进程继承了连到柜台的管道，关闭柜台 15 秒超时  |
| pilot6 `b13eae13` | `Start-Process`（ShellExecute，不继承句柄），交接走启动时环境变量 | 重放：health 12.7 秒、open 1.9 秒回报且柜台侧管道随即关闭；安装态维护旅程通过 |

维护旅程（pilot6）连续 4 次通过（`run-98ea98e5`、`run-e3497fb6`、`run-83b63d32`、`run-00ee8b76`）：
退出柜台后在维护窗口完成自动备份计划往返（改为 23:17、保留 24 份/365 天后改回）、立即自动备份并校验、GUI 创建并校验备份、
演练所选备份、整店导出并校验，备份与业务数据无意外变化。

## 3. 恢复目标与备份计划

ADR-98 §4 要求的字段。软件默认值来自 [ADR-79](../../adr/2026-10-03-adr-79-windows-scheduled-backups.md)：每天 03:00 备份，保留 14 份/30 天，剩余空间低于 2048 MiB 提醒，每 7 天恢复演练一次。

**关键事实：电脑关机或未登录时不会执行计划备份。** 门店夜里通常关机，03:00 的备份会推迟到第二天开机后补跑，所以当天的账可能一整夜都没有备份。

| 字段           | 建议值                                                                   | 依据                                                   | 你的决定 |
| -------------- | ------------------------------------------------------------------------ | ------------------------------------------------------ | -------- |
| 每日备份时间   | **打烊交班后**，如 21:30（在“备份与恢复”里改）                           | 保证当天营业数据当晚落备份；软件每天只支持一个计划时间 |          |
| 本机 RPO       | 最多丢失 **1 个营业日**；交班后再点一次“立即备份”可缩到几乎为零          | 每日一次自动备份 + 交班手工备份                        |          |
| 离机副本与 RPO | 两块加密 U 盘或移动硬盘**每周轮换**，离机 RPO ≤ 7 天；口令与介质分开保管 | ADR-78 加密离机归档；同机备份不能替代（ADR-98 §3）     |          |
| RTO            | 本机恢复 **≤ 2 小时**恢复营业；换机恢复 **≤ 1 个营业日**                 | 尚无实测，须在走查第 C 部分计时后确认或调整            |          |
| 留存           | 保持默认 14 份 / 30 天                                                   | 软件允许 2–24 份、1–365 天                             |          |
| 空间提醒阈值   | 默认 2048 MiB；照片多时调到 5120 MiB                                     | 按走查时实测的备份大小决定                             |          |
| 恢复演练间隔   | 保持每 7 天                                                              | 演练只读影子库，不动营业库                             |          |

## 4. 故障发现与停止条件

柜台的备份逾期、空间不足等提醒**只显示在柜台“设置 → 备份与恢复”里，不会推送到手机**。

| 字段         | 建议                                                                                                                                           | 你的决定 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 每日检查     | 店长**开门时**看一次“备份与恢复”摘要：最近备份时间、提醒、剩余空间；写进开闭店检查表                                                           |          |
| 最长响应时间 | 发现提醒后 **1 个营业日**内处理；处理不了联系升级联系人                                                                                        |          |
| 升级联系人   | 写一个能远程排障的人和联系方式                                                                                                                 |          |
| 停止条件     | 出现任一情况立即停止新业务写入并保留现场：未知收款结果过夜未核清；交班对账差额核查后仍不为零；恢复或演练失败；员工越权或权限异常；维护状态不明 |          |

停写后按 ADR-98 §5 和 [ADR-80](../../adr/2026-10-03-adr-80-windows-schema-upgrade-rollback.md) 成对回退，由两位管理员复核后才恢复写入。

## 7a. 签署前仍缺、需要你或门店提供的证据

以下是自动化做不到、必须有人或物到场的部分（详见准入手册的证据矩阵）。

- **普通店长真人走完业务闭环**：按 [门店走查清单](store-walkthrough.md) 第 B 部分。
- **门店同级电脑流畅度**：ADR-99 的 60 帧门禁，同一清单第 A 部分；软件内“检测流畅度”给出客观数字。
- **换机、换用户恢复**：在第二台实体电脑、不同 Windows 用户上，用离机介质恢复一次并计时。
- **Windows 11**：如果门店或备用机是 Win11，需要在 Win11 上装一次、走一遍。
- **v1 真实只读副本**：第 7 节授权后才能做零差异 dry-run。
- **长时间运行**：至少连续营业一周的备份与提醒记录。

Linux Server/Web 产品面。本计划取代历史 [V2-M2 → V2-M6 实施计划](2026-07-19-v2-m2-m6-implementation-plan.md)

## 2. 收口定义

本计划中「Web 产品收口完成」必须同时满足：

1. **版本可追溯**：部署 marker 与目标 Git SHA 一致，对应 `workspace-check` 和 `real-postgres` 双绿。
2. **环境边界不放宽**：仅使用合成数据；PostgreSQL 仅 loopback；公网入口保留会话、Origin、Fetch Metadata、CSRF 与限流。
3. **核心业务纵向闭环**：双管理员与员工凭据、价目、开单/部分收款/欠款、履约/上架/取衣补齐、退款/交班均有可回读证据。
4. **会员纵向闭环**：档位、充值与赠送、余额支付、剩余本金退款、冻结/解冻/关户均有可回读证据。
5. **经营面闭环**：催取候选与人工名单、双口径日/月/职员报表及导出与合成流水一致。
6. **证据分层清楚**：公网 UI/HTTP、真实 PostgreSQL、软件模拟与实体/正式发布门禁分别记录，不相互冒充。
7. **未收口项显式 pending**：只要任一必验项缺新鲜证据，整体状态仍为「执行中」。

## 4. P2 业务验收顺序

1. **投产与价目**：核对两位独立管理员、员工凭据生命周期和可开单价目。
2. **柜台工作日**：合成顾客 → 开单 → 部分收款 → 履约/上架 → 取衣补齐 → 退款/独立欠款处理 → 历史空营业日交班。
3. **会员生命周期**：开户/档位 → 充值赠送 → 余额支付 → 本金退款 → 冻结/解冻 → 原子关户。
4. **经营面**：为 30/90/180 天催取候选构造受控历史时间数据，生成经审计名单；对日/月/职员双口径报表与 CSV 逐项反推。
5. **真库债务**：对剩余 capturing pools 逐文件分类。保留 SQL 形状、参数整形、预校验、单语句/N+1 与 PG 错误映射单元证据；补齐任何缺失的真库行为证据。

脚本级 blocker 是 30/90/180 天催取正向数据；远端浏览器 UI 仍作为独立证据层 pending。

## 5. 执行约束

- 只使用带唯一标识的合成顾客、手机号、订单和会员数据；禁止真实 PII。
- 不直接套用现有本地 Playwright global setup 到共享云库：它依赖本地 PG 与固定 fixture，会覆盖共享状态。
- 交班只关闭受控的历史空营业日；不关闭当天营业日，避免冻结后续写入。
- 催取候选必须有 30/90/180 天历史时间。未有经审计的云端时间 fixture/runbook 前，该项保持 pending。
- 证据记录不包含密码、token、cookie、数据库口令或真实手机号。
- 发现真实缺陷时，先加最小回归再修复；若改变命令/查询或对外能力边界，按 ADR-16 同批增加 ADR 与 CHANGELOG 证据。

## 6. 不在本次「Web 产品收口」内

- 生产级多租户云部署、SLA、容量规划与跨店/跨设备同步；
- Windows 打包与实机适配；
- Apple Developer ID、公证/staple/Gatekeeper 与正式签名更新权威；
- 可访问的双架构 OCI 发布物与干净机安装；
- XP-58 中文、金额、扫码、走纸、切刀与断连实体验收；
- AI/BYOK、短信/微信自动通知、v1 真实数据迁移。

这些门禁仍要分别关闭，但不阻塞 ADR-36 定义的 Linux Server/Web 产品面收口。

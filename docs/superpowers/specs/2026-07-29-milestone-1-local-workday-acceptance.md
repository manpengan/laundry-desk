## 3. 过程中查出的实质缺陷

这些是里程碑最有价值的产出——它们都曾经带着**全绿的测试套件**存在于 `main`：

1. **`business_date` 约束拒绝一切合法日期。** 迁移 0019 把正则写成 `'^\\d{4}-...'`，
   `standard_conforming_strings=on` 时 `\\d` 匹配的是字面反斜杠。结果是真实 PostgreSQL 上
   **每一次开单与收款都失败**。能出厂是因为订单/支付测试全用 capturing pool（断言 SQL 文本
   的 mock），**从没有任何测试通过生产路径写入过一条真实订单**。
2. **Electron 壳装着旧 SPA。** 柜台 UI 改动没有回灌构建产物，壳内缺整个柜台界面。
3. **全新安装开不了单。** 价目表无种子数据，而冻结的契约面只有价目查询没有写入命令——
   唯一途径是绕过应用直接写库。
4. **CI 分层遮蔽。** turbo 的 lint 跑在 test 之前，一个行数超标错误挡住了上面两个缺陷；
   「红灯报出来的那条」不等于全部。

## 4. 现在守着这些的门禁

- **`main` 分支保护**：required status checks = `workspace-check` + `real-postgres`，
  `strict` + `enforce_admins`。直推被拒（实测 GH006），一切走 PR。
- 两个 workflow 的 `pull_request` **不带 `paths` 过滤**——被 skip 的 required check 永远不
  报告，会把 PR 永久卡死。
- 真实 PG 门禁要求 **`# skipped` 为 0**，防止 PG 用例悄悄退化成跳过。
- 柜台工作日现在有三层回归网：服务端命令总线、浏览器、macOS 打包应用。

## 6. 加固补记（2026-07-29）

按上文建议补浏览器覆盖时，又查出三个**只有端到端才能发现**的缺陷。它们都不是
「测试没写」，而是功能本身不可用：

5. **R3 二次确认在 HTTP 上根本走不通。** 客户端用裸 `{ confirm_ref }` 作为请求体
   回复确认，但路由只在请求体带 `command`/`mode` 等信封键时才按信封解析，于是这个
   body 被当成命令参数去校验、必然 `VALIDATION_FAILED`。**任何 R3 命令都无法从浏览器
   完成**（`order.cancel`、UI 上的 `shift.close`）。服务端测试测不到，因为它们直接调
   `executeCommand` 并用 `confirmRef` 选项，根本不经过路由。
6. **订单与欠款页从未接入路由。** 产品设计 §5.1 把「订单与欠款」列为首期导航项，但
   `nav.ts` 没有该项、`PageHost` 没有该分支，于是 `DebtPage`、`OrdersList` 与
   `OrderDetailDrawer` 三个组件**在运行的应用里完全不可达**——它们有单测、被 barrel
   导出，但没有任何页面渲染它们。
7. **订单状态标签与真实枚举脱节。** `StatusBadge` 的 order 映射里是 `voided`（不存在
   的状态），缺 `draft` 与 `cancelled`；未命中时回退成原始英文值，中文界面上会直接
   显示 `cancelled`。

现在挂单/撤销、独立补缴、订单列表与详情都已进浏览器 E2E。

## 7. 照片与工作日加固补记（2026-07-29）

- 交班浏览器验收固定使用 `1999-12-31` 的空营业日，不冻结当天柜台。
- 照片文件名和存储 key 仅由服务端生成；文件目录/文件权限为 `0700` / `0600`。
- 上传限制 JPEG/PNG/WebP、8 MiB、文件数与总字节配额，校验文件头和 SHA-256。
- 照片目录只接受固定 Compose 挂载点，并在所有权标记验证后才调整权限；非空未知目录和
  符号链接路径 fail-closed。
- HTTP 上传/下载要求服务端会话租户、CSRF、Origin/Sec-Fetch-Site 和专用限流；通用
  `photo.register` HTTP 命令入口被拒绝。
- HTTP、IPC、React 三层严格校验照片成功结果，拒绝 `storage_key` 越界；照片查询失败会
  显示可重试错误，不再伪装成空列表。
- Electron 只暴露命名照片 IPC，打包清单已包含其传输依赖；真实 `.app` 在服务中断后
  恢复，并验证照片记录跨重启仍存在。
- 新增关键真实 PG 回归 4/4、0 skipped，覆盖完整计价、统计/现金、交班/audit 和照片
  metadata 回读。

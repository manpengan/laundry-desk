# ADR-84：Windows Counter 签名自动更新与完整性回退

- 状态：软件实现、独立审查与原生解包验证通过；完整签名安装更新待验证
- 依据：ADR-72 A6；仅活动 V2 Counter，Cloud 暂停；Runtime/数据库跨迁移联合恢复另见 ADR-80

## 更新边界

Windows 复用既有 Ed25519 更新清单、固定 HTTPS 来源、精确长度与 SHA-256、A/B 槽、离线队列清空、Primary lease 阻断、安全版本下限和启动确认状态机。清单增加可选的签名 target；Windows 必须精确匹配 win32/x64 和 generic/hongfa profile，Mac 原清单不变。Counter 本机队列 schema 变化拒绝自动升级，转联合迁移，不改变数据库 schema。

更新入口仅来自包内的固定配置与公钥，渲染层不能指定下载 URL、可执行文件、证书或 shell。未配置更新源的开发包保持关闭。`release:update:win` 需要明确源码 SHA、Windows 证书存储中的签名身份、Ed25519 密钥对、固定来源配置、版本及回退政策；只产生本机 NSIS/ZIP/清单，不上传或部署 Cloud。当前发行 profile 的 development_only 标记继续保留，不能据此视为宏发生产准入。

## Windows 验证

固定系统 PowerShell 原生桥使用参数化标准输入，限时、限量，清理继承环境并检查系统路径与 ACL。ZIP 每项拒绝绝对路径、`..`、设备名、替代数据流、反斜线别名、重复大小写名、链接和特殊文件；限制数量、单文件及总展开大小。只向新建私有目录写入，不覆盖文件。

候选 EXE 必须具有有效 Authenticode，签名证书与当前版本一致，版本匹配签名清单；profile、更新源和公钥须保持一致。证书或更新权威轮换通过独立安装流程实施。暂存健康探针不占用运行中柜台的单实例锁；验证后写持久激活记录，在下一次启动切换，窗口和运行环境就绪后确认。

每次启动更新槽前重新验证签名 ZIP、精确摘要及展开目录的全部字节和文件清单。首次建立更新状态时保存原安装目录完整文件摘要，包含 EXE、DLL、ASAR 和资源；回退原位必须重新验证该基线以及签名和更新权威，不能只检查 EXE 或 ASAR 是否存在。已有状态缺失原位证明不得自动重新登记。

已确认槽的文件损坏同样触发失效标记及健康槽回退，不反复指向坏槽。回退即使目标就是当前快捷方式启动的位置也必须验证完整性；两个槽都不可用或回退低于安全下限时进入既有只读恢复模式。旧槽和失败证据保留，不在更新时删除数据。

## 验证状态

本地 27 项测试覆盖清单目标绑定、schema 限制、ZIP/更新权威篡改、下载正文超时、已确认槽损坏、原 ASAR 修改与安全下限。Windows 系统 PowerShell 脚本解析及原生 ZIP 测试通过；原生测试使用已签名系统 EXE 的临时副本且不执行该副本，确认正常解包、内容篡改与五类异常路径拒绝。完整已签名 Counter 的安装、自动切换、故障回退仍须最终实机门禁，不能用静态解析或模拟桥代替。

正式证书、公开更新源、生产准入和真实业务数据的门禁保持独立；本轮不自动建立公开更新服务。

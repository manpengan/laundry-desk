# ADR-96：订单中心与客户历史的有界分页

- 状态：Accepted（依据 2026-10-06 全量优化实现授权；不构成真实数据生产准入）
- 作用范围：活动 V2，本机 Windows 桌面与共用 Web 柜台界面。

## 背景

订单与欠款入口此前仅显示最多 50 张欠款订单；客户历史固定最近 20 单。较早的已结清订单没有完整浏览入口。

## 决定

扩展已有 `order.list` 到 0.3.0，不新增命令或查询名，不修改 `m2-freeze.test.ts` 名单。
保留旧的营业日、状态、手机号、余额下限与 limit 参数；新增 exact `ticket_no`、exact `customer_id`、字面量 `customer_query`、营业日起止、`ready_for_pickup` 和 `offset`。待取定义为至少一件处于 `racked`，与欠款无关。所有结果保持原整数分。

页大小默认 20、最多 50；offset 0–1,000,000，超出范围必须缩小日期条件。分页结果包含 `orders`、`total`、`offset`、`limit`。PostgreSQL 用同一 SQL 快照计算总量与当前页，只为当前页计算衣物数，排序为创建时间、票号、订单 ID 递减。所有筛选在服务端执行，租户范围仍来自会话与现有 RLS。查询词在审计中掩码，不使用 SQL LIKE 通配符解释用户输入。

订单中心在原导航入口提供全部、欠款和待取视图；所有视图共用筛选、详情和分页。客户历史使用稳定客户 ID，避免更换手机号后仅能看到新号码订单。刷新失败保留上次成功结果并显示持续错误，页码只在成功响应后变化。

客户工作区按历史订单、档案与预约、会员、合并与隐私分区。切换分区保持组件和输入草稿；选中另一位客户则按客户 ID 重建工作区。当前客户身份持续可见，会员余额与权益摘要显示在分区上方；风险操作单独分区并重复显示目标身份。

## 门禁

覆盖 50/51 欠款、20/21 及更多客户订单、较早已结清订单、票号/客户/日期/状态组合、字面量查询、空尾页和跨租户隔离；UI 覆盖失败保留、分页、分区与目标切换。真实 PostgreSQL 测试须在统一候选上执行；桌面/窄屏及 Windows 测试由最终集成门禁给出，不以组件测试代替。

Cloud 暂停、公开 HTTPS 功能隐藏、打印延期及真实数据准入约束保持有效。

# ADR-100：扫码优先的专业工作台（方案 E）

- 日期：2026-10-18
- 状态：已实现，待 manpengan 走查签署（含 Windows 实机 60fps 门禁）
- 范围：`apps/web` 工作台页面（`CounterWorkbench` 与 `pages/workbench/`）、`packages/ui` 三个新图标、Web 包 CSS 预算
- 授权：manpengan 在会话中选定设计方案 E（A 专注扫码 + B 驾驶舱融合）并要求“按 E 方案开始实现”，单次授权 Claude 实施本页改版；不改变 [ADR-66](2026-08-29-adr-66-windows-hongfa-pilot.md) 的 owner 分工

## 背景

原工作台是“快捷取衣 + 顾客速查 + 几个数字 + 最近订单”，信息单一，店员要跳到别的页面才知道今天该处理什么。manpengan 要求做到专业级别的工作台。设计稿 E1（1440×900）、E2（搜索下拉 + 深色）、E3（1366×768 店员视图）在 Design 画布中评审通过。

## 决策

### 1. 布局

自上而下：标题行（问候、营业日、实时更新时间、刷新）→ 扫码区（一个输入框 + 开单 / 取衣大按钮 + 挂单 / 收欠款）→ 五个今日指标 → 工作队列（左）与今日节奏、生产进度、接下来（右）。每块独立加载、独立失败，读不到时只在本块说明，不弹全局提示；可见时每 120 秒自动刷新。

### 2. 只用现有查询，不新增契约

| 区块                     | 查询                                                                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 今日 / 昨日指标          | `stats.day.summary`（昨日带 `business_date`）                                                                                                         |
| 工作队列                 | `order.list`：未取件 `status=open`；已上架 `ready_for_pickup`（仅开启履约）；超 30 天 `status=open, date_to=今天−30`，最早的在前；挂单 `status=draft` |
| 欠款                     | `order.list` 分别读 `status=open` 与 `status=closed` 且 `min_balance_cents=1`，合并；挂单整单金额记在余额里但不是欠款，永不计入                       |
| 今日节奏                 | 今日与昨日 `order.list`（按营业日）的开单时间，只计 `open`/`closed`，与日汇总口径一致                                                                 |
| 生产进度、货架、衣物摘要 | `fulfillment.workbench`（received / washing / ready+racked，各至多 100 件，满页显示“100+”）                                                           |
| 接下来                   | `delivery.appointments.list`（仅开启取送）与 `shift.get`（仅店长）                                                                                    |

### 3. 角色

- 店长（`admin`）：今日实收、营业额（账目口径；无账目字段时回退为“收款（退款前）/ 开单应收”）、收衣、取走、欠款金额；看日结交班提醒。
- 店员（`staff`）：未取件订单、收衣、取走、超 30 天未取、欠款订单——只有单数，不显示营业金额。队列里每单的待收金额两种角色都显示，取衣时要收。

### 4. 交互

- 扫码框：Enter 后并行查 `order.lookup`（未取件）与 `customer.search`；唯一订单直达取衣；多结果下拉，↑↓ 选择、Enter 打开、Esc 关闭；无结果提示按客户查找。只有聚焦时显示强调色外框，提示扫码会落在这里。
- 队列行：挂单“继续开单”；已取走仍欠款的订单“收欠款”，转订单与欠款（取衣页只能对未取件订单收款）；其余“取衣”。未上架时货架列显示进度（已收件 / 洗涤中 / 待上架 / 已取走）。
- 队列列头吸顶；↑↓ 在行间移动焦点。

### 5. 性能与样式

- 图表全部是 SVG 属性绘制，无内联 style（CSP）；只用 `--lg-*` 令牌；动画只用 transform / opacity，且仅 `data-motion="full"`。
- 吸顶列头与扫码下拉在深色主题下要不透明：把半透明表面叠在 `--lg-bg` 上，不加 `backdrop-filter`。
- Web 包 CSS 总预算由 160 KiB 提高到 176 KiB（本页约 14 KiB 页面样式；构建后 174,821 B）。

## 后果

- 工作台每次刷新约 15–25 个只读查询（大多一页即止），均有上限；不新增服务端负载类型。
- E2E 约定保持：`工作台` 标题、唯一“刷新”按钮、`counter-workbench-metrics` / `counter-workbench-orders`、`input[name="quick-pickup"]`、店长账目说明文案。
- 未实现设计稿里的“最近扫码”记录（需在本机保存顾客信息，暂不做）和开班时长（无开班时间查询）。

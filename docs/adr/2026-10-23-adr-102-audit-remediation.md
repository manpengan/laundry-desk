# ADR-102：全面审查的账务完整性与 Windows 配对交付修复

- 日期：2026-10-23
- 状态：技术修复已授权；验证进行中，不代替 ADR-98 的运营准入
- 基线：main `ba18b2f3d13104c31b82de456ee2a872260dd599`
- 范围：活动 V2、合成数据；Cloud 暂停、v1 冻结、打印暂缓

## 原因

全面审查实际复现了余额撤单未回补会员账、照片重试误删原文件、退款后核券破坏历史付款投影、未来营业日提前关闭。
同时，默认 Windows Counter CI 未把同源 Runtime 绑定进 EXE，依赖门禁出现新公告；旧 Windows unit15 暴露发布目录比暂存目录更长的路径失败。
这些问题不能由原有绿色构建或旧候选的安装成功证明已解决。

## 决策

1. 新增 `0083_member_payment_links.sql`，将会员 spend 分录与订单付款建立不可变、租户内唯一关联。
   已有数据只依据精确的 `member.balance.pay` 审计证据回填，无法验证时不猜测。撤单按原分录的本金/赠金做 reversal，
   支付冲正、会员账、订单状态与审计在同一事务中完成。冻结账户可退回且保持冻结；已关闭账户拒绝整笔撤单。
   合并顾客后仍退至原账户。并发与幂等不允许重复退款；异常必须全量回滚。
2. 图片存储明确返回新建/复用。规范存储根下同 upload ID 的写入、登记、失败核验串行；复用文件永不补偿删除。
   只有明确登记失败且权威存储确认无引用的新建文件可以清理；提交结果不明或清理查询失败保留并记日志。
   锁是单 Runtime 进程内互斥，不提供多个 Runtime 共用照片目录的支持承诺。等待或写入后重新核验会话和 CSRF。
3. 优惠券只适用于从未有任何付款账本行的订单。净已收为零不等于从未收款。
   PostgreSQL 在订单锁内判断；内存写入函数也做原子保护。拒绝后订单、券与付款历史均不变，重新收款和撤单仍可执行。
4. `shift.close` 在取得营业日锁和读取快照前，按服务器时间、门店时区与换日小时拒绝未来营业日。
   不用客户端日历或所选历史快照推断“今天”。历史交班能力保持；界面提供明确说明及本地化错误。
5. 未新增 Command/Query；公开错误 detail 增加 `member_account_closed`、`member_payment_unlinked`、
   `coupon_payment_history`、`future_business_date`，用于准确提示未执行的原因。M2 command/query 清单不变。
6. Counter 打包必须有同源 Runtime 入口；静态检验 ASAR 中实际绑定、源码 SHA、manifest 与入口摘要。
   CI 调用 Runtime 可复用工作流获取同次运行产物，两种 profile 分别绑定；保留原 Runtime push/PR 检查入口。
   安装后再次检验绑定并执行真实 PostgreSQL 与原生维护窗口测试。保留 clean-source、哈希、签名状态与 development_only 门禁。
7. 安装前计算最终哈希目录和完整 payload 路径长度，超过现有安全边界即拒绝，早于 Programs、快捷方式和实例写入。
   普通路径与特意构造的深路径分别回归，不通过缩短测试目录掩盖真实边界。
8. Electron/Fastify/Vitest 升级见[依赖审计](../operations/dependency-audit.md)。旧引擎 IME 特例不自动扩展到新版本。
9. 内存适配器的会员账户、账本、支付关联及订单、付款、衣物和票号统一在事务快照中暂存。
   审计与 COMMIT 成功前不对其他事务发布；冲突检测拒绝依据过期快照提交，不能靠即时写入后的 CAS 逆操作修复并发派生状态。
   回归同时覆盖审计失败与 COMMIT 失败、并发现金付款，以及退款、核券、取衣对未提交状态的不可见性。
10. 新支付关联表同步登记整店导出精确列清单与租户矩阵，exporter 仅获四个 UUID 列的按店读取权限。
    portable 导出/恢复以实际本金、赠金、支付关联和两侧冲正引用验证全字段保留。
    实测旧反向引用查询扫描 50,500 条合成账本后，在同一未发布迁移中增加非唯一部分索引，保留识别旧 NULL 订单冲正的语义。

## 验证与验收记录修订

本批修改使旧候选的源码与依赖身份失效，不能沿用旧 Windows/账务验收结果。
此前[最终验收记录](../operations/windows-final-acceptance-20261018/progress.md)与
[初始化现场材料](../operations/windows-store-initialization-20261021/onsite.md)仍保留历史事实，当前进展以
[整改记录](../operations/audit-remediation-20261023/progress.md)为准。

必须完成源代码/内存回归、真实 PostgreSQL 回归、独立复审、固定源码配对打包、同候选 Windows 安装与合成业务/恢复验收。
Windows 原生入口8项通过只关闭该安装入口缺陷，不代表完整候选或门店真人验收。
只有用户明确授权后才能提交/推送；没有 clean commit 时不伪造发行 SHA 或放宽打包门禁。

# ADR-74：Windows 旧版 SQLite 正式迁移

- 日期：2026-10-03
- 状态：实现与合成数据验收中；不构成真实顾客数据准入批准
- 接续：ADR-14、ADR-16、ADR-66、ADR-71、ADR-72、ADR-73

## 裁决

Windows V2 提供管理员迁移入口。柜台上传独立、已停写的 v1 SQLite 备份并预览数量、金额、日期替代和照片关联；管理员重新输入当前密码后，服务端生成 10 分钟有效的一次性请求。组织、门店、员工和会话版本均从当前身份推导，客户端不能选择目标数据库、租户、照片目录或任意本机路径。

维护程序只接受请求 ID。它持现有排他操作锁、停止柜台及服务、创建并验证数据库与照片联合安全点，再以 `laundry_app` 执行导入、对账并恢复运行。不能由 HTTP 处理程序停止自己后继续执行，也不能将外部 SQL 交给管理员角色执行。

新增 HTTP 能力为 `/api/v2/migrations/v1/drafts` 上传、`/:draftId/photos/:photoId` 上传、`/:draftId/review` 预览及 `/:draftId/authorize` 批准。桌面只暴露有限的 `migration.execute` 操作；Zod 校验输入和输出、固定路由及上传大小。所有入口要求当前本机租户的管理员兼隐私管理员、CSRF、限流；批准复用现有密码验证与登录限流，失败进入脱敏安全事件，成功批准和实际导入均有审计。请求正文、密码及源数据不进入日志。

## 映射与保全

- 顾客、订单、订单行、逐件衣物、已收款和照片进入当前 PostgreSQL 表；金额始终使用整型分。原员工 ID 不授予新系统权限。原衣物名称和备注放入现有衣物详情备注；超过 256 字符显示契约时阻断，不截断。
- 原始可空时间、会员统计、旧状态、旧付款方式、员工 ID、取衣日期、照片路径等未被当前字段表达的内容进入 `v1_import_legacy_records`，绑定批次和顾客。它不是当前业务权威账本。
- v1 取衣码允许重复，V2 要求门店内唯一。唯一旧码保留；重复码生成确定的新码，原码完整保留在历史元数据。预览明确显示替换数量，原订单号保持不变。
- 旧照片仅属于整单，因此确定地关联该单第一件衣物；预览必须明确说明并由管理员确认。照片按原相对路径逐个上传，禁止链接、绝对路径及路径逃逸。文件、元数据 SHA-256 和大小均校验，批准绑定完整照片清单摘要。
- `shop.name` 和 `price_templates` 按严格类型保留为历史设置，不能把旧设置自动激活为 V2 配置。未知设置、未知表或未知列阻断，避免静默遗漏。
- 冻结 v1 的 `staffs`、`sms_log`、`audit_log` 作为严格字段的受限历史保存。提取器从不 SELECT `password_hash`，预览明确给出排除凭据数量；旧账号不会激活，旧短信不会重发，旧审计不会进入当前权威审计表。
- 历史短信优先按订单或准确手机号关联顾客，冲突阻断。原审计差异可能混杂多个顾客，因此任一顾客匿名化时，同一事务删除该组织全部导入审计及无法归属顾客的历史短信；已归属资料按顾客删除。界面明确披露该保守规则。工作人员自身历史保留，不恢复其凭据。

## 数据库与恢复保证

`0070_windows_v1_import.sql` 增加非 PII 批次收据、可清除历史资料及短期批准请求三张表，全部强制 RLS。收据只有摘要、映射版本、计数、安全点和操作人；不存一份永久姓名、手机号或备注副本。批准请求仅存会话版本与摘要。

导入事务确认当前连接是非超级用户且无 BYPASSRLS 的 `laundry_app`，重新检查当前管理员权限、会话/权限版本和请求有效期，再获取组织迁移锁。首次导入要求目标组织无顾客、目标门店无订单或旧批次。确定 ID、全部字段读回对账、请求消费和审计在一个事务内完成；审计失败必须回滚全部业务写入。重试只能核对同一已消费请求与既有批次，不追加第二份业务记录或审计。被隐私清除或其他业务修改后的数据不能通过旧批次重放复活。

照片先写入不可变、校验过的存储。数据库失败或提交结果不明时保留可验证的孤立文件，避免删除可能已提交的照片；既有照片孤立清理机制负责后续回收。

## 源数据边界与临时文件

源 SQLite 上限 64 MiB，表行数上限 100000，字段文本上限 65536；最多 100000 件衣物、1000 张照片，单照片 8 MiB、照片合计 128 MiB。提取只操作私有副本，使用 readonly、query_only、trusted_schema=OFF 和完整 integrity_check；拒绝 WAL/SHM/journal 伴随文件，不加载扩展。字段、关联、金额及计划完整性二次校验，不能用手改计划或报告绕过。

数量和关联验证位于 transform 的第一步，在逐件展开前拒绝超限数量；零单价不能绕过衣物总量上限。批准持久化函数在运行时重新投影三个摘要字段，不能依靠 TypeScript `Pick` 排除密码等多余对象属性。PG 回归主动传入额外合成密码并核对审计仅含摘要与有效期。

预览目录必须为当前 Runtime 私有照片目录的同级 `import-requests`；根和 UUID 子目录均有身份 marker。预览 30 分钟过期，批准最多再保留 10 分钟。成功完成、过期请求及重启遗留草稿均只删除自己创建且校验通过的私有目录。重启遗留目录使用超过 1 小时的保守清理阈值；成功导入但文件清理失败返回明确 `cleanup_pending`，后续清理重试。

## 依赖与验收

服务端依赖 `@laundry/migrate-v1`，普通服务入口使用纯 JavaScript `./plan` 导出，仅在源提取时动态加载 SQLite。Windows 发布必须在独立 Windows checkout 使用 Node 22 x64 原生安装/重建 `better-sqlite3`，实际读取合成 SQLite 后再打包；禁止复制 macOS `.node`。

验收使用仓库合成 SQLite 和隔离 PostgreSQL 16。`tools/data-transfer/run-pg-fixture.mjs` 生成随机端口和临时凭据，应用全部当前迁移，执行 app-role 回归后销毁自己创建的容器，不触碰用户数据库。必须覆盖：完整字段读回、零差异、幂等、跨租户不可见、收据不可改、审计故障全回滚、旧资料同事务隐私清除、管理员/CSRF/限流、会话切换和资料过期。

本 ADR 不解除真实顾客数据准入门禁。实际 Windows 维护桥、原生 SQLite ABI、已安装版本端到端测试需另附新鲜证据；代码构建和本机合成 PG 通过不能替代这些验收。

# ADR-24：账目双口径与有界日/月/职员报表

- 日期：2026-08-07
- 状态：**Accepted**
- 决策者：manpengan
- 前序：[ADR-03：件级衣物 / 订单行 / 账务状态模型](2026-07-19-adr-03-garment-order-accounting-model.md)、[ADR-18：储值核销单列对账](2026-08-01-adr-18-stored-value-settlement-reporting.md)、[ADR-23：催取人工名单](2026-08-07-adr-23-pickup-reminder-manual-list.md)
- 路线：[V2-M4 账务双口径](../superpowers/plans/2026-07-19-v2-m2-m6-implementation-plan.md#3-v2-m4-账务双口径--老板端--备份还原)

## 背景

当前 `reconciliation.day.get` 能核对一个营业日的订单、支付流水、交班、打印与离线
回放，但它是诊断快照，不是经营账目：没有日期区间、月结或职员归集，也没有把
ADR-03 已冻结的「真实收入 / 业绩收入」做成可见、可导出的产品口径。

会员储值进入主线后，两种收入天然不同。充值当天有真实资金流入但没有洗衣业绩；
余额消费当天产生洗衣业绩但没有第二次资金流入。若继续只展示「支付合计」，店主会在
充值日高估业绩、在核销日低估业绩，且无法解释银行/钱箱与营业额的差异。

## 决策

### 1. 冻结两种口径

- **真实收入** = 订单支付流水中非 `balance` 方法的有符号净额 + 会员账本中带
  `tender` 的本金有符号净额。
- **业绩收入** = 全部订单支付流水的有符号净额，包含 `balance`，不包含会员充值
  与储值退款。
- **储值核销** = `payments.method = 'balance'` 的有符号净额；它进入业绩收入，
  不进入真实收入。
- **储值资金流** = `member_ledger.principal_delta_cents` 中带 `tender` 的净额；充值
  为正、退本金为负，赠送额永不进入真实收入。
- 支付退款与红冲沿用只追加流水语义：退款为负；红冲退款为正；红冲其他支付为负；
  红冲的渠道取被引用流水的不可变 `method`，不信任红冲行自行携带的渠道。

因此结果必须同时展示：订单外部收款、储值资金流、储值核销、真实收入和业绩收入，
不得只给一个无法复算的总数。

### 2. 新增一个查询与一个命令

- `accounting.report.get`（R2）：按营业日区间读取双口径报表，支持 `day` 或 `staff`
  分组；缺省日期由服务端按门店时区与切日时刻确定。
- `accounting.report.export`（R3）：对同一冻结筛选生成确定性 UTF-8 CSV 与 SHA-256，
  审计只保存筛选、行数和摘要，不保存 CSV 正文。

日期区间最多 366 个自然日，结果最多 366 行；可选 `staff_id` 只能作为过滤条件，
租户和门店仍只从服务端会话注入。两项能力均在线专用、要求 `accounting_read`；导出
额外要求 `ledger_export`，且必须经过 R3 确认卡。

### 3. 渠道与归属

报表固定展示 `cash | wechat | alipay | other | balance` 五个渠道。前四个渠道可同时
含订单外部收款与储值资金流；`balance` 只含订单储值核销。职员归属取每条不可变
流水的 `staff_id`，不按订单创建人倒推。

PostgreSQL 查询同时依赖 RLS 与显式 `(org_id, store_id)` 条件。会员账本是 org 级
可读表，报表必须显式过滤 `store_id`，不得把同组织其他门店的充值带入本店。

### 4. 本片范围

本片交付 Linux 本地 Server + Web 的今日、往日、月结和职员账目视图，以及经审计
的 CSV 导出。现有单日对账与交班继续保留，不改变已冻结快照。

本片不包含老板端 H5/PWA、AI 经营分析、备份还原 UI、云端多店汇总、Windows 或
macOS 验收。`accounting.report.get` 暂不加入当前 AI 工具投影，后续开放需另行追认。

## 契约冻结影响

- 命令：35 → **36**，新增 `accounting.report.export`。
- 查询：21 → **22**，新增 `accounting.report.get`。
- `m2-freeze.test.ts` 与 PR 描述必须点名上述两项变化（ADR-16 §2）。

## 后果

- `packages/domain` 成为双口径归集的唯一纯函数真源；PG 与 memory source 只提供
  已签名的流水聚合行。
- 新增报表索引只做 expand，不修改或删除历史流水。
- 对外能力边界、CHANGELOG、README 与里程碑验收订正必须同批更新。

## 否决的备选

- **把充值和余额消费都算营业额**：同一笔钱会在充值和消费时重复计入，否决。
- **只看现金/银行，不算余额消费业绩**：核销日的实际服务产出消失，否决。
- **按订单应收确认业绩**：会把尚未收回的欠款混进收入，且与现有只追加支付账本
  无法逐笔核对，否决。
- **浏览器自行拼报表或 CSV**：口径会与服务端漂移，导出也没有审计证据，否决。

# ADR-95：订单价目名称快照

状态：实现接受；来源为 2026-10-06「全部优化实现」授权。此裁决不放行真实数据。

新客户端选择价目时提交稳定的 `catalog_code`，服务端仅接受当前门店活动价目中编码、服务和品类同时一致的项，从该项读取显示名称与单价并一同写入订单行。客户端提交的名称不参与权威快照。未知或停用编码、编码与服务/品类不一致时拒绝开单。确认挂单时保留所选编码并重新按当时有效价目解析；完成单后修改价目不重写历史名称。

增加 `order_lines.catalog_name`、`catalog_code` 可空列（0082）。编码是历史快照，不对可变价目表建立外键。旧订单保持空值，界面退回已有代码名称映射，不将今天的价目名伪造成历史快照。旧客户端未提交编码时仍按既有服务/品类计价：唯一候选可保存名称及编码；多个同价候选允许继续开单，但两个快照字段均为空，避免将第一项伪装成用户选择；多个不同价候选仍拒绝。`order.get` 在行和衣物投影中返回字段；取衣、订单详情和挂单恢复优先使用快照。导出白名单与加密恢复草稿同步支持编码。

价目维护会去除名称首尾空白，禁止空白名称。已有异常空白或超长名称在服务端计价阶段返回受控业务错误，不留到数据库 CHECK 失败。数据库保留名称/编码约束，导出角色仅增加这两列的 SELECT 权限。

复用既有 `order.receive`、`order.hold` 与 `order.get`，不增加命令/查询名，m2-freeze 清单不变。快照名称最长 128 字符、编码最长 64 字符，金额仍为整型分。验证包括同分类多价目选择、价目改名后的旧单读取、新单采用新名、挂单恢复与确认、客户端伪造名称隔离、旧客户端歧义回退、异常名称业务错误、停用项拒绝和导出完整性。

# ADR-86：小程序顾客身份与门店显式委托

- 日期：2026-10-03
- 状态：实施中，真实微信凭据、域名与手机联调另列验收
- 裁决：本轮 manpengan 授权 B3/B4；Codex 负责实现与独立审查

## 身份

Windows 本机配置固定租户；客户端不能提交租户、员工、数据库地址或 API 基址。
微信登录 code 由服务器向固定 `api.weixin.qq.com` 换取 openid。
首次关联须取得同一小程序授权的手机号，仅关联本门店已有且未匿名化的唯一 canonical 顾客。
持久映射使用域分离 HMAC；为订阅通知保留的 openid 使用独立 `miniapp_recipient` AAD 加密。
openid、微信 session_key 和平台 access_token 不返回客户端。

顾客得到最长 15 分钟的随机 `m1.` 令牌。有效身份同时要求服务进程内存映射和数据库
会话／绑定／配置版本均有效；重启、注销、配置修改和顾客匿名化均不能恢复旧授权。
凭据通过 Windows DPAPI CurrentUser 包装数据密钥和 AES-GCM 密文保存；普通读取接口不返回密文或明文。

## 有限交易授权

管理员重新输入密码，显式开启自助交易并指定一名当前有效的履约员工。默认关闭。
每次顾客交易均在事务内重读并锁定配置版本、委托员工及其权限版本、顾客会话、canonical 归属和业务资源。
员工权限撤销立即影响顾客操作。不能签发员工令牌，也不提供任意员工总线入口。

管理员委托与顾客本次原生确认共同构成独立的顾客操作策略：仅允许本人预约创建／取消、
余额支付、权益消费、支付意图创建及地址维护。原员工和 AI 总线的 R3/R4 确认流程保持。
业务规则复用既有领域 handler／仓储；业务变更、原业务审计、顾客会话与委托版本回执在同一事务提交。
退款继续走既有 R4 审批，不向顾客提供直接退款命令。

## 资金与外部调用

金额为整数分，金额与余额均由数据库读取；微信支付成功回调只代表客户端提交，
仅支付通道核验的服务商结果可记账。创建意图与顾客回执同事务，外部发送在提交后执行。
未知支付不创建新扣款；同幂等键重放须相同顾客、动作和输入，且当前授权仍有效。
跨页面重启的未决意图由服务器列表与排他规则保留。

## 数据与恢复

新增迁移 0077/0078 将配置、身份映射、短会话、订阅同意及不可变交易回执纳入租户 RLS。
跨机业务导出排除凭据和身份会话；恢复暂停配置、撤销短会话，保留业务交易与审计证据。
回执只保存资料版本、预约或业务资源标识等有限结果，不复制地址、手机号、openid 或 JSAPI 支付签名。
订阅接口记录顾客原生明确接受的已配置模板；通知发送由 ADR-90 的独立显式发送链处理。

资料写入继续使用受限 `SECURITY DEFINER` CAS，保留原有 portal 地址 DML 防护。
仅凭应用账号可写的会话行和租户 GUC 不构成该函数的授权：服务端还须提交独立 HMAC，
绑定动作、租户、当前会话、顾客、委托员工、配置版本、完整修改内容、资料版本和最长 60 秒期限。
资料版本 CAS 阻止证明重放。普通应用账号不能读取或修改 `miniapp_profile_authority`。

权威密钥由本机访问令牌秘密通过独立 HKDF 域派生。Runtime 在核对迁移包、账本和本机身份后，
用单独 owner 连接初始化或轮换验证密钥；HTTP 进程不持有 owner 数据库连接。
跨机包排除该密钥，恢复验证时重新绑定当前实例秘密，旧证明不能恢复旧授权。

## 验证

协议测试覆盖固定目标、大小和时限及异常；真实 PostgreSQL 回归覆盖顾客隔离、授权证明伪造／篡改／过期／重放、
撤权、幂等、预约、权益、事务失败与资金保护。结果以新鲜测试输出为准。
无真实外部凭据时不将模拟协议结果记为微信生产验收。

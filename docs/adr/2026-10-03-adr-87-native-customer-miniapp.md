# ADR-87：原生顾客微信小程序

- 日期：2026-10-03
- 状态：Accepted（ADR-72 授权 B4 实现）
- 前序：ADR-71、ADR-72、ADR-85、ADR-86

## 决策

新增 `apps/customer-miniapp` 原生 WXML/WXSS 前端；复用活动 V2 的严格结果契约及顾客专用交易面。
微信 code2session/手机号核验与商户签名均在 Windows 服务端，客户端不接收 AppSecret、session_key、
商户凭据、员工会话或租户参数。固定 HTTPS 来源在构建时配置，运行时不读取二维码或输入的服务 URL。
本 ADR 不恢复 Cloud 产品开发部署，不创建公网入口。

顾客登录使用内存短会话；页面卸载、退出和认证失效中止请求并清除显示。身份切换前创建的回调，
包括原生登录、确认、付款与随机请求标识，均不能写入新身份。业务请求以服务端会话限定本人归属。
支付和充值必须人工操作；原生支付窗口返回不视为收款，唯有服务端核验结果可以显示已支付。
失败重试使用原幂等键，未决付款从后端读回并阻止重复发起。退款仍经柜台原有复核面。

功能包括本人订单、衣物状态与收据、预约及取消、地址新增、余额及流水、充值/支付、券/次卡/积分，
以及逐项自愿订阅提醒。次卡和积分按服务端既有规则记录消费，客户端不推导价格或承诺现金抵扣。
首个取送选时明确使用中国标准时间；不支持的店铺时区拒绝创建并提示联系门店，不默用手机时区。

## 理由与备选

使用微信原生登录、支付和订阅边界并共享 Zod 契约，避免 H5 Cookie 与小程序身份混用。
不持久化 token，不把失败付款按成功入账，不在前端引入支付或短信密钥。沿用官方原生项目结构，
独立打包客户端，无 CloudBase 依赖。

## 验收与后果

客户端有类型/lint/构建与协议行为回归；原生模板和样式通过本机微信开发者工具自带编译器。
当前开发者工具未登录且无实际 AppID，模拟器启动在 AppID 校验处阻断，不能记为模拟器通过。
真实 AppID、合法域名、隐私指引、手机号能力、批准模板、支付商户和受控可达入口仍须分别验证。
本轮所有测试仅用合成身份和协议夹具，不发送真实通知或扣款。

接口协议、顾客交易权限与渠道核验另见 ADR-85/86；所有功能状态由本轮实施清单记录。

# ADR-83：衣物图片辅助与掉标候选比较

- 日期：2026-10-03
- 状态：实施中，待本批独立审查与 Windows 验收
- 关联：ADR-72、ADR-75、ADR-82

## 决策

在 Windows 助手提供衣物外观建议和掉标候选比较。员工选择一张目标图片，或再选择最多两张本店衣物照片，逐次同意发送给已配置的模型供应商。结果仅为类别、颜色、可见特征和候选相似程度，不写订单、不改变归属、不批准取衣、不发送通知。认领仍需员工核对实物与票据。

没有新增业务 Command/Query 或数据库权限。使用专用、封闭的 `POST /api/v2/ai/vision/candidates` 与 `/analyze`，复用 `ai.execute` IPC 的结构校验、主进程凭据和注销取消。不能传 URL、路径、模型名或供应商地址；请求租户来自当前服务端会话，要求 `ai_use` 与 `order_write`，且必须为已配置的本机门店。

## 图片与同意边界

查询复用本店履约工作台，最多展示六张缩略图，不带顾客姓名、手机号或身份信息。分析请求中的候选仅为员工已选的照片 ID 和 SHA-256；服务器重新检查照片所属租户、有效记录、哈希和受保护文件存储。模型只收到从 0 开始的图片标签，比较结果只允许候选序号，服务器逐项对应本次请求，拒绝缺少、重复或越界候选。

目标图片先在客户端限为 8 MiB、JPEG/PNG/WebP，缩到最长边 512；服务端再次验证图片格式、单页、最多 1600 万像素，旋转并重编码为最长边 512 的 JPEG。每张外发图最多 49,152 字节，移除 EXIF 等元数据；最多三张图片。原始图片与编码不会写入 AI 会话、审计或错误日志。会话仅保存用途、同意标记、目标图片哈希及候选绑定。图片内容仍可能包含顾客信息，界面要求员工先裁剪人物、票据和顾客资料再逐次同意。

## 模型与预算

复用 A7 的本机 DPAPI 密钥托管、凭据租约、固定 HTTPS 出站目标和每次配置版本复核。DeepSeek 当前适配器拒绝图片；Gemini 仅允许本地能力清单或明确支持图片的固定型号；Anthropic 未列入能力清单时，通过官方模型接口确认 `image_input.supported` 后才分析。模型响应采用封闭枚举，任何工具调用和非结构化结果均失败关闭。

单次分析限制输出 512 token，复用原 AI 预算预留、用量结算、审计和熔断；每会话每分钟六次、每组织三十次，服务器最多并发两次，12 秒后取消。重复 request_id 不启动第二次付费推理；停止、关窗、注销及权限失效沿原取消/授权链处理。用量越界沿 ADR-82 的实际扣账或扣尽预留并停用配置流程，不能以零用量绕过预算。Gemini 的思考 token 计入输出用量，思考文本不展示。

## 验证与外部依据

本地合成测试覆盖真实图片解码和去元数据、照片租户与哈希、权限与 CSRF、同意、取消、模型能力拒绝、严格输出、工具拒绝、重复请求、预算不足、异常用量停用及桌面取消。真实 PostgreSQL 测试验证停用配置与扣账审计的原子性和进程重建后的持续拒绝。本批未使用真实外部密钥，未把本地协议测试计为供应商或 Windows 安装形态验收。

官方接口依据（2026-10-03 核对）：[Anthropic 图片输入](https://platform.claude.com/docs/en/build-with-claude/vision)、[Anthropic 模型能力](https://platform.claude.com/docs/en/api/models/retrieve)、[Gemini 图片型号](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)、[Gemini generateContent 与用量字段](https://ai.google.dev/api/generate-content)。适配器保持现有固定端点，不接受任意 base URL。

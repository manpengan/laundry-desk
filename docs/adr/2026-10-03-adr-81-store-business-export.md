# ADR-81：Windows 整店业务与照片导出

- 状态：实现验收中；真实数据准入仍遵循 ADR-66 / ADR-71
- 日期：2026-10-03
- 范围：A9。打印开发和 Cloud 部署均不在本次范围。

## 问题与决策

店主需要可独立查阅、逐项清点的数据交接包。加密换机包包含实例权限状态，不能直接充当业务导出。新增独立的整店业务导出流程，沿用 A2 的 PostgreSQL 文本值、逐表游标、清单与摘要原则，但使用自己的显式非凭据字段清单，不调用全库转储，也不执行外来 SQL。

设置页的“整店业务导出”先展示范围与排除项；管理员兼隐私管理员确认个人资料范围并重新输入当前密码。服务端派生 org/store/actor/session，生成 10 分钟一次性请求。界面只获得请求编号。Windows 维护工具接收该编号与新的目标文件夹，持操作锁、暂停柜台后执行导出，再恢复服务。不得从渲染器传入数据库地址、SQL、租户或服务端文件路径。

新增固定 HTTP GET/POST `/api/v2/store-export` 和 IPC `desktop:store-export:operation`。HTTP 使用现有登录密码校验、共享密码失败限流、安全事件与 CSRF；响应使用统一信封。只绑定当前 Windows 本地发行租户。命令与查询注册表未扩展；业务没有直接写入口。

## 范围与字段保全

`store-export-schema.ts` 冻结实际 PostgreSQL 每个业务表、全部字段与类型（含生成列）；`store-export-policy.ts` 显式分类。安装库出现未评审表、新增列或类型变化时阻断导出。每包生成完整 `data-dictionary.json`，含实际导出字段、PostgreSQL 类型、数据范围和每项排除理由。

- 店级交易、生产、配送、营销、短信、审计和 AI 记录只取当前店。
- 顾客、会员、组织设置等共享资源按组织导出。字典明确标记共享范围。
- 非秘密 AI 模型注册表属于全局资料；组织与店铺身份均显式绑定请求范围。
- 员工密码/PIN、供应商凭据密文、会话与刷新令牌、离线签名授权、设备认证、提权证明、执行审批/租约与重放状态不进入包。历史业务结果保存在原交易/用量/审计表。
- 业务记录中的执行租约、认证会话引用和打印 capability/payload 路径单独排除；每列均列入字典。
- 通用设置与 JSON 业务记录出现密码、私钥、API 凭据等键时阻断导出，不能把不明凭据混入明文包，也不静默丢字段。普通业务文本仍可能包含人工输入的个人资料，界面明确提示个人资料范围。
- 所有数据库值通过 PostgreSQL `::text` 导出为 UTF-8 JSON Lines，null 保留为 JSON null。金额分、大整数、bytea 和时间不会经过 JavaScript 浮点转换。时间固定 UTC，值保持换行与原始字符。避免 CSV 公式执行问题。

## 权限、一致性与发布

0073 保存请求范围、权限/会话版本、策略摘要、期限、Ed25519 签名、消费时间和包清单摘要，不保存密码、密钥、导出文件路径或顾客资料。表开启 FORCE RLS，app 可创建票据，但签发后的字段只允许更新消费时间与清单摘要；数据库触发器令已提交消费回执不可清空或替换，防止 SQL 重置后重放原签名。授权、消费与对应审计分别在事务中完成。

HTTP 密码复核通过后，用本实例 access-token secret 经独立 HKDF 域 `laundry-desk/store-export-approval/v1` 派生 Ed25519 密钥。规范化签名绑定 request/org/store/actor/session、权限/会话版本、策略摘要、批准时间与到期时间。公私钥、原始秘密均不入库或输出；worker 的信任根来自本机私有 secret 文件，不能由票据指定。

换机恢复会将未消费导出请求的 `revoked_at` 置为当前时间；worker 拒绝已作废请求，目标实例的独立密钥也不能验证源实例签名。不会伪造成功消费时间或清单摘要。

普通 app 角色不获得导出读取权限，也不能通过 GUC 或自建票据放宽 AI 会话与内部表的 RLS。新增 `laundry_store_exporter` 为 NOLOGIN/NOSUPERUSER/NOBYPASSRLS 独立只读角色，app 不得成为其成员。逐表、逐字段静态 GRANT 与店/组织 RLS 和数据字典一致，密码等排除列在数据库权限层也不能读取。

只有固定离线维护 worker 使用 Runtime 已有管理连接（固定本机数据库），进入 repeatable-read 事务立即降为 app 角色，锁定一次性请求及当前员工、角色、会话；复核管理员、隐私管理员、权限版本与期限，并以独立信任根验签。通过后才切换只读导出角色生成快照，最后切回 app 消费并写审计，全部同一连接、同一事务。普通 HTTP 进程没有管理连接或专用角色。所有查询另有参数化 org/store 条件；导出期间不以管理身份读取。角色切换为事务局部，结束后关闭专用连接池。

照片只读取本快照引用的 `garment_photos` 与 `delivery_evidence_attachments`，经两个 PhotoFileStore 校验真实文件、类型、字节数和 SHA-256。孤立文件不导出；任何缺失或不匹配令整包失败。字典、表文件与照片都列入 manifest；manifest 记录源照片表与记录 ID，便于关联。

目标目录必须全新、绝对路径，拒绝已有目录、符号链接父路径和 Runtime 根目录内路径。先创建私有 ACL 的 staging，所有文件私有写入并 fsync。全包重读校验后才消费请求并写审计；提交后将 staging 原子改名为 `data`。失败不显示成功、不发布部分包；审计提交后若文件发布失败须重新授权，不把旧编号重新启用。

导出上限为 3 GiB，总引用照片 20,000 张、每张 8 MiB，每行 16 MiB、每表 5,000,000 行；超过即报错，不截断。manifest 的 SHA-256 由维护工具独立显示。校验命令同时检查此摘要、清单内文件摘要/字节数和不明附加文件；摘要是完整性凭据，不是数字签名。

## 验证与限制

使用隔离 PostgreSQL 16 合成租户、真实 app/专用只读角色和照片文件验证全表导出、租户隔离、金额/大整数保真、凭据排除、一次性请求、撤销会话、缺照失败回滚、文件篡改与既有目标拒绝。额外验证 app SQL 伪造票据无效、不能 SET ROLE、不能读取内部表、签名与字段篡改和跨实例重放失败、只读角色不能查询密码列。HTTP 验证匿名/普通员工/CSRF/租户注入/错误密码限流，桌面验证固定路由与会话切换。Windows ACL、维护 GUI、打包安装与 Session 1 验收由 Windows 批次统一执行。

当前输出 `assurance: development_only`。本包用于查阅和交接，不是实例恢复包；恢复应走 A2。不得据此绕过本机形态真实顾客数据准入 ADR。

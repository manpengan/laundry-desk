# ADR-98：Windows 本机受控试点生产准入提案

- 日期 / 最后核对：2026-10-06
- 状态：**Proposed，待 manpengan 签署；真实顾客数据与真实记账尚未放行**
- 提案整理：Codex；最终决策者：manpengan
- 前序：[ADR-66](2026-08-29-adr-66-windows-hongfa-pilot.md)、[ADR-71](2026-10-02-adr-71-cloud-platform-pause.md)
- 执行与证据：[本机准入手册](../operations/project-remediation-20261006/local-admission.md)
- 范围：纯本机 Windows V2 的 W2/W3 准入；不新增 Command/Query，不恢复 Cloud，不改变资金和权限规则。

## 背景与当前效力

ADR-71 暂停了 Cloud 生产路径，但没有免除 ADR-66 的生产恢复、数据责任和试点门禁。
本轮“全部优化实现，完了再次测试后提交推送”授权软件实现、测试与提交推送，不等于签署生产准入。
本提案把本机形态所需证据、责任与切换流程列全，供最终候选完成验证后审阅。

本文件处于 Proposed 时，不替代 ADR-66/71 的现行约束。即使本 ADR 随代码合并或所有自动化测试通过，
也不能把 development-only 安装器改称生产包，不能导入真实顾客资料或开始记真实账。

## 拟定决策

### 1. 本机准入以一个明确的发行组合为单位

接受本提案后，拟用以下门禁替代 ADR-66 W2/§8 中依赖 Cloud 的基础设施路径；Windows 安全、权限、
迁移与数据责任继续有效。该替代须在签署记录中明确生效，不能由实施者自行推定。

- 固定一个源代码提交、锁文件、发行 profile、Counter/SPA、Runtime、迁移摘要和安装器哈希。
- 柜台只连接获准的本机 Runtime；测试实例、生产候选、备份与证据目录各自有明确归属。
- 在独立合成实例完成验证后，再按签署的切换方案初始化生产实例；不得把已有 QA 实例改名当作生产。
- 同源软件组合取得本地检查、真实 PostgreSQL、远端 CI、Windows 安装态结果；每类证据分别记录。
  Windows Server CI 不替代目标 Windows 10/11、用户 SID、DPAPI、DPI、IME 与操作员验收。

### 2. 数据责任与最小开放范围先于真实数据

manpengan 指定数据责任人、日常店长、备份保管人、独立复核管理员及故障接替人，记录授权范围和交接方式。
两个管理员必须为独立身份；单个 agent 不能同时代签批准和验收。

签署时明确店铺、机器资产编号、Windows 专用账号、操作员、试点日期、营业时段、允许启用的能力和每日核对要求。
Cloud 保持暂停；顾客小程序、微信通知、远程协助等公共 HTTPS 入口保持隐藏。
本轮打印工作继续暂缓：打印能力不得计为通过，是否允许一个不启用打印的限定试点须由签署者明确裁决。
电子秤只保存经确认的订单备注，不能参与计价。

真实短信、支付、AI 或设备功能逐项取得账号、授权和实测回执后才启用；未验收项保持关闭。
生产准入本身也不替代发送真实消息、收费、退款或向模型提交顾客照片的具体业务授权。

### 3. 签署前必须关闭的门禁

| 门禁       | 必需证据                                                                              | 不足时的处理                      |
| ---------- | ------------------------------------------------------------------------------------- | --------------------------------- |
| 发行与安装 | 同一候选的 Counter/SPA/Runtime 绑定、干净安装、升级、卸载重装保留状态、权限与签名政策 | 保持 development-only，仅合成数据 |
| 本机安全   | 专用 OS 身份、私有 DACL、DPAPI 可用、离线与恢复权限撤销、普通店员越权拒绝             | 停止可写试点                      |
| 离机恢复   | 加密数据库及两域照片归档、独立介质、第二台机器及不同 Windows 用户恢复、逐项核对       | 同机备份或影子演练不能替代        |
| 故障发现   | 备份关闭、逾期、空间不足、维护中断、离机介质缺失的发现与责任人响应记录                | 不把柜台绿色状态当作已通知责任人  |
| 容量与长跑 | 约定订单/照片规模、持续运行窗口、备份耗时、剩余空间与留存边界、失败后恢复             | 未测负载不写成容量承诺            |
| 迁移与切换 | 获授权的 v1 checkpoint 只读副本、零差异 dry-run、照片匹配、计数/金额核对、演练回退    | 不读取或修改门店 live SQLite      |
| 运营闭环   | 普通店长独立完成开单、补缴/退款、取衣、交班、备份、故障恢复和每日对账                 | 开发者脚本通过不能替代操作员完成  |
| 数据责任   | 责任人、访问范围、保留/删除规则、丢失申报和停止条件书面确认                           | 不导入真实顾客数据                |

恢复、迁移和演练沿用现有受信维护入口，不增加绕过权限或直接修改库的运维旁路。
真实生产数据的首次迁移、恢复和重新开放写入均由两位获授权管理员复核。

### 4. 恢复目标与故障阈值须明确裁决

以下字段尚未决定，不沿用 Cloud ADR-65 的目标作为本机承诺：

| 待决策项 | 签署时须填写的内容                                                   |
| -------- | -------------------------------------------------------------------- |
| RPO      | 最多可接受丢失的业务时间；本机备份与离机副本分别约定                 |
| RTO      | 从宣布故障到恢复可核对、可继续营业的最长时间                         |
| 备份计划 | 营业/停写窗口、每日时间、留存份数/天数、离机轮换与加密口令保管       |
| 故障响应 | 逾期和空间阈值、责任人实际可收到的提示方式、最长响应时间与升级联系人 |
| 容量/SLO | 订单数、照片数量/大小、运行时长、操作延迟和允许停机窗口              |
| 停止条件 | 对账差额、恢复失败、未知收款、权限异常达到何种条件即停写             |

软件默认值只作为配置初值。签署前须在候选机器读取实际配置、验证计划任务的实际执行和离机副本轮换。
界面显示“备份成功”只证明对应动作结果，不能证明 RPO、RTO、独立介质或通知送达已经满足。

### 5. 事故处理与回退

发生未知收款、重复开单、账目不一致、备份不可恢复、权限异常或未知维护状态时，先停止新业务写入并保留现场。
记录最后成功交易/备份时间、发行摘要、固定错误码和维护阶段；秘密、顾客字段及票据正文不进入工单或公开证据。

程序和数据库结构必须按 [ADR-80](2026-10-03-adr-80-windows-schema-upgrade-rollback.md) 成对回退：
回退前保存当前数据库与照片安全点，再选择该发行对绑定的旧程序和旧快照，撤销旧执行授权后核对账目。
升级后的业务数据保留在回退前安全点，不能声称自动并入旧结构。
数据库回退不能撤销已经发生的支付、退款、短信或通知，恢复后先核对外部结果，禁止盲目重发。

维护日志不明、OID/摘要不匹配、受信备份缺失或安全点创建失败时，保持停服并保留数据。
不得删除维护记录、重建空库、手改版本指针或复用新的请求身份来绕过失败。
恢复后由责任人与独立复核人共同确认计数、账目、照片、权限和备份状态，再单独批准恢复写入。

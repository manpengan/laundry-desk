# ADR-92：柜台开单操作身份与未确认结果

状态：实施中；随本次 UI 修复 PR 验证。范围为活动 V2 Windows 柜台，不恢复 Cloud。

## 原因

开单完成后原表单可以重复提交；只按业务内容缓存幂等键，也会把人工核对后新开的相同内容订单误判为旧单重试。切页丢失输入与启动期固定连接状态进一步增加误操作。

## 决定

- 每次开单工作区生成独立 UUID `operationId`。重试固定原操作身份和原请求体，明确开始新单或人工核对后结束旧操作才重新生成。
- CommandPort 增加可选 operationId；现有 `desktop.command.execute` IPC 增加严格 UUID 字段 `operation_id`。该字段只作为幂等缓存的操作命名空间，不写进业务 HTTP body。主进程自行生成实际 Idempotency-Key，renderer 仍无法指定请求地址、headers、token 或实际幂等键。
- 主进程缓存按服务端会话、门店、员工隔离。二次确认引用沿用首跳 key；普通 token 刷新不改变操作身份。未知结果继续保留 key，明确成功或明确拒绝才释放。
- 带操作身份的开单在在线尝试后结果不明时，不再自动以新 key 转入离线队列，避免已提交业务恢复后再次收款。当前开单保留输入并等待原操作重试；服务不可达期间不能将这笔现金收款宣称为已完成。既有离线队列与离线只读恢复保留。
- 未暂存输入仅在当前员工的内存工作区保存；切页保留，切员工先提示，刷新及关窗有确认。提交中或结果未知时停止修改和普通重提。
- 连接提示来自实时健康及实际离线队列；未知、冲突、断开时不得显示全部已同步。

没有新增 Command/Query，M2 冻结清单保持原有 85 个命令、67 个查询。幂等键不代替服务端权限、事务或审计检查。人工结束只释放界面，不撤销、不补记业务；操作员必须先核对订单和收款。

## 验证

覆盖立即连续提交、成功后再次提交、提交已落库但响应丢失后的重试、人工核对后同内容新单、确认请求丢响应、切员工隔离及未知同步状态。安装态验证与后续批次进度见 `docs/operations/ui-ux-20261005/`，不以单元测试替代 Windows 实测。

# ADR-99：六套主题配色与液态玻璃动态效果分级

- 日期：2026-10-07
- 状态：已实现，待 manpengan 走查签署（含 Windows 实机 60fps 门禁）
- 范围：`packages/ui` 设计令牌与交互基元、`apps/web` 员工端外观设置；沿用 [液态玻璃 UI 2.0](2026-07-18-liquid-glass-ui-2.md) 的六条语汇与红线

## 背景

manpengan 要求进一步优化 Windows 桌面端 UI：做 5–6 套可切换主题，全局实现液态毛玻璃动态效果，提升视觉动感与审美。

现状只有浅色 / 深色 / 跟随系统三档。画布是两团静态光晕，侧栏和顶栏的模糊几乎透不出颜色。UI 2.0 的呼吸背景、磁性焦点、数字滚动没有落地。镜面追光与涟漪因担心 CSP，在桌面端整体关闭（`enableLiquidGlass={host.kind === "browser"}`）。另一方面，提交 ea65b85b（弹层去掉全屏模糊）已证实部分门店电脑是软件渲染，全屏模糊会卡顿，所以动效必须能按设备降级。

参考：Apple Liquid Glass（玻璃只用于导航层、不叠玻璃、按内容调色、滚动边缘效果）；Fluent 2 的 Mica / Acrylic 与减速曲线；Chromium 对 `backdrop-filter: url(#svg)` 位移折射的支持情况。

## 决策

### 1. 外观由三个设备偏好组成

| 偏好 | 取值                                                                                          | 本机存储键                 | 落在 `<html>` 上                       |
| ---- | --------------------------------------------------------------------------------------------- | -------------------------- | -------------------------------------- |
| 配色 | `sky` 晴空（默认）· `sea` 海盐 · `bamboo` 青竹 · `sakura` 樱花 · `amber` 暖阳 · `aurora` 极光 | `ld.counter.palette`       | `data-palette`                         |
| 明暗 | 浅色（默认）· 深色 · 跟随系统                                                                 | `ld.counter.theme`（沿用） | `data-theme`                           |
| 动效 | 自动（默认）· 标准 · 节能 · 关闭                                                              | `ld.counter.motion`        | `data-motion`：`full` / `calm` / `off` |

三者都只保存在这台电脑上，不进服务端、不新增 IPC 或契约。宿主入口在 React 渲染前调用 `bootAppearance()`，登录页和首帧就是所选主题。顾客页有自己的配色，不受影响。设置 → 外观与快捷键提供六张主题卡片（每张卡片带自己的 `data-palette`，局部预览该配色）、明暗与动效分段控件；命令面板增加“配色：…”六条命令。

### 2. 六套配色只覆盖“种子”令牌

令牌按层叠顺序拆分为：`core-tokens.css`（晴空默认值）→ `themes.css`（配色种子）→ `glass.css`（材质）→ `aurora.css`（背景与动效分级），入口仍是 `@laundry/ui/styles.css`。

- 每套配色在浅色和深色下各定义十个种子：`accent`、`accent2`、`accent-strong`、`accent-fill`、`accent-fill-hover`、`bg`、`aurora-1…4`。
- `accent-soft`、`accent-ring`、画布光晕、深色卡片与弹层的轻微色调由 `color-mix()` 从种子派生，不逐套手写。
- 正文墨色、语义状态色（在洗 / 待取 / 逾期 / 已结束）不随配色变化，符合 UI 2.0“语义色独立于品牌色”。
- 深色规则比浅色多一级特异性，与导入顺序无关。

### 3. 动效分级

| 档位        | 何时生效                                                                     | 行为                                                                           |
| ----------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 标准 `full` | 自动 + 有显卡加速；或手动选择                                                | 极光漂移、镜面追光、涟漪、页面与面板入场、数字滚动、弹性弹层、主题切换交叉淡化 |
| 节能 `calm` | 自动 + 软件渲染（SwiftShader / WARP / llvmpipe，或拿不到 WebGL）；或手动选择 | 背景静止，不追光、无涟漪；保留按压、磁性滑块（220ms 无过冲）与原有 250ms 弹层  |
| 关闭 `off`  | 手动选择；**系统“减少动态效果”开启时总是强制**                               | 所有动画与过渡归零                                                             |

软件渲染只在“自动”时用一次性 WebGL 上下文探测（`failIfMajorPerformanceCaveat`），结果缓存。系统明暗与“减少动态效果”变化会实时生效。

### 4. 动态效果清单（全部只动 transform / opacity）

- **呼吸极光**：固定层上四团配色光场，26–38 秒交错漂移，配静态胶片颗粒消除渐变色带。光场放在四角，侧栏和顶栏背后总有颜色，中部阅读区保持安静。
- **三层玻璃**：侧栏、顶栏、登录卡为窗口玻璃（`blur(24px) saturate(1.8)` + 内高光边）。卡片仍不模糊。
- **磁性焦点**：侧栏当前页是一枚玻璃胶囊，分段控件是一枚滑块，切换时 FLIP 位移并带液滴形变；尺寸瞬时设定，动画只作用于 transform。
- **镜面追光 / 液态涟漪**：每帧最多一次布局读取；只在标准档运行。
- **数字滚动**：工作台看板加载时数字从零滚动到实际值（850ms easeOutCubic）；服务端渲染、测试与其他档位直接显示最终值。
- **主题切换**：View Transitions 交叉淡化 380ms；过渡期间页面仍可点击（`::view-transition { pointer-events: none }`）。
- **滚动边缘**：内容滚到顶栏下方时出现柔和阴影，由 scroll-driven animation 在合成线程完成。

### 5. 桌面端在 CSP 下启用液态玻璃

`installLiquidGlass` 只通过 CSSOM（`style.setProperty`、`style.width`）写入，不写 `style` 属性、不插入 `<style>`、不用 `data:` 资源。主题实验页套用与 `app://` 相同的 CSP 实测：涟漪尺寸、追光坐标正常生效，控制台没有违规。因此两端都启用（`spa-host-contract.test.ts` 改为锁定这一点），`liquid-glass.test.ts` 锁定源码不出现被 CSP 拦截的写法。

### 6. 对比度与性能门禁

- `theme-contrast.test.ts` 直接解析发布的 CSS，对 6 套 × 深浅共 12 种组合按柜台实际叠放方式合成背景后计算 WCAG：
  - 按钮文字（含渐变两端）≥ 4.5；
  - 强调文字在卡片、侧栏胶囊与纯画布上 ≥ 4.5；
  - 焦点色在卡片上 ≥ 3；
  - ink / ink2 在光场最强处的画布上 ≥ 4.5；
  - ink / ink2 / ink3 在卡片与玻璃上 ≥ 4.5；
  - 五种状态胶囊 ≥ 4.5。
    实测页面审计确认画布上只有标题（ink）与说明（ink2），强调色和弱化文字都在卡片或玻璃上。
- 为通过上述门禁：浅色 ink3 不透明度 0.64 → 0.66；深色“已结束”墨色 `#a1a1a6` → `#b1b1b6`（原值在深色卡片上为 4.39，属既有欠账）。
- 同屏 `backdrop-filter`：侧栏 + 顶栏 2 层，打开 AI 面板或抽屉时最多 4 层；弹层遮罩仍不模糊。
- CSS 总量 146,208 → 161,424 字节，仍在 163,840 字节预算内。

## 否决的备选

- **SVG 位移折射（`backdrop-filter: url(#lens)`）**：只有 Chromium 支持，大面积使用 GPU 开销高。透镜位移图通常用 `data:` 图片，会被桌面 CSP 拦截。保留为后续可选的小面积实验。
- **Electron `backgroundMaterial`（Mica / Acrylic）**：只支持 Windows 11 22H2 及以上，门店常见 Windows 10。
- **运行时生成主题样式**：`<style>` 文本被 CSP 的 `style-src 'self'` 拦截；静态 CSS 也便于测试对比度。
- **每套主题手写完整令牌（12 套全量）**：维护成本高，容易漏改；种子 + `color-mix()` 派生更稳。
- **主进程 `nativeTheme` IPC 推送明暗**：渲染进程 `matchMedia` 已能实时感知，不值得新增契约面（ADR-16）。

## 后果

- 设置页明暗分组的可访问名称由“主题”改为“明暗”，新增“主题配色”“动态效果”；Windows 安装态 E2E 已同步，并增加配色切换断言。
- 深色主题的首帧仍可能短暂显示 Electron 窗口的浅色底（`backgroundColor` 在主进程固定）。若走查发现明显闪烁，再评估由 Runtime 设置窗口底色。
- CI 的无 GPU 环境会解析为“节能”，自动化测试不受漂移与入场动画影响。
- “Windows 实机 60fps”仍需 manpengan 在门店同级设备上走查：标准档的页面切换、涟漪连点、列表滚动。若不达标，先把“自动”的判定收紧到节能，不回退设计。

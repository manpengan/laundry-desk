# ADR-72：Windows 全功能补齐与分批交付

- 日期：2026-10-03
- 状态：Accepted（manpengan 本轮会话明确授权 A1–A9、B1–B8）
- 交付负责人：Codex
- 前序：ADR-66、ADR-68、ADR-71

## 决策

本轮实现此前功能差距清单的 A1–A9 与 B1–B8，使用多 agent 分工，按功能分别提交并推送
GitHub 交付分支。完成集成后，构建活动 V2 的 Windows 安装包，通过既有固定密钥 SSH
连接 Windows 测试机，执行安装后的功能与维护验收。提交、推送、构建、安装、实测分别记录。
代码存在或模拟测试通过不等于已在目标 Windows 或真实外部渠道完成验收。

打印机相关开发、打印验收以及依赖打印口的钱箱驱动本轮暂缓；B7 仅实施电子秤接入。
旧打印失败现场保留，不为本轮开发重放打印。Cloud 平台继续按 ADR-71 暂停开发与部署，
不更改现有云环境。顾客端及远程支持使用独立的本地/受控开发环境验证，其生产网络形态另列。

本轮包含：Windows 照片和联合恢复、加密离机备份与换机恢复、定时备份维护、跨迁移升级恢复、
旧版正式迁移、Windows 更新、AI/BYOK 接通、脱敏诊断、整店导出，以及通知、支付、顾客自助交易、
原生小程序、AI 受限操作与分析、视觉辅助、电子秤、受控远程协助。

短信供应商由 manpengan 指定为阿里云。支付按微信支付 API v3 与支付宝实现，顾客端使用原生
微信小程序。服务商协议只依据官方文档；没有真实渠道配置时使用明确标记的协议夹具验收，
产品不得返回模拟发送、支付或模型调用成功。不得提交秘密或真实顾客数据。

## 实现约束

- 复用活动 V2、统一 Command/Query、服务端租户上下文、整数分、同事务业务与审计。
- 各功能另附针对性 ADR；新增命令、查询和外部能力同时更新契约及验收范围。
- 数据恢复、跨实例导入和旧版迁移有显式选择、预恢复点、内容摘要、幂等和中断恢复；
  不因功能补齐而删除现有数据库、备份、工作区或失败证据。
- 本机秘密使用操作系统保护与私有文件权限；渲染进程不持有供应商密钥。
- AI 写操作仍经人工确认/必要复核与同一命令总线；不开放数据库、shell、任意网络或恢复工具。
- 远程协助仅限用户明确授权、重新认证、可撤销、有期限的只读诊断，不提供任意 shell。
- 生产 JS/TS 默认 400 行，测试不超过 800 行；共享文件由集成负责人协调，避免并行覆盖。
- 每批运行相关行为回归、类型与静态检查；重大功能安排独立安全、语言和数据库审查。

## 完成口径

[实施清单](../operations/2026-10-03-windows-full-feature-batches.md) 逐项记录实际实现、测试、
提交、推送与 Windows 安装验收。真实短信/支付/微信、视觉准确性、电子秤硬件、生产网络与
正式运行准入所需外部条件单独记录；不得用测试替身替代外部完成证据。
本 ADR 授权开发和合成测试，不授权向真实顾客发送消息、扣款、导入真实数据或恢复 Cloud 部署。

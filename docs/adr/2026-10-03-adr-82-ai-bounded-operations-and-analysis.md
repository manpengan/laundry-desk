# ADR-82：AI 受限操作、催取辅助与经营分析

- 日期：2026-10-03
- 状态：实施中，待本批独立审查与 Windows 验收
- 关联：ADR-72、ADR-75、ADR-62、ADR-05

## 决策

Windows 助手在原有日汇总、脱敏检索与规程工具上，增加三个封闭工具。

| 工具                 | 输入与结果边界                                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `business.trend`     | 仅 7 或 30 日；读取已有经营看板，分别汇总经营收入与实际收入，金额为整数分，说明口径与日期，不把差额判断为利润或异常。                    |
| `pickup.candidates`  | 仅 30/90/180 天、欠款筛选和最多 10 个当前候选；删除姓名、手机号和顾客 ID，保留票号、订单 ID、件数、余额、滞留天数及来源。                |
| `operations.preview` | 仅 `garment.bulk_transition`、`garment.rework`、`notification.manual_list.create`，最多 10 个对象；始终调用既有总线 `dryRun`，不能执行。 |

衣物检索复用 `records.search` 的 `garments` 范围，返回本店条码、状态、位置和衣物 ID，排除顾客资料。新增工具仅允许当前配置的本机门店，按服务端会话注入租户与权限。没有增加业务 Command/Query，也没有修改 `m2-freeze` 清单。

## 确认与权限

R3 总线保存原始入参、业务状态摘要和有效期到既有 `ai_pending_actions`。服务器将有限确认卡放入认证后的 `tool_result` 事件；模型只收到“尚未执行”，收不到 nonce、确认能力或执行结果。用户核对独立卡片后，专用 `POST /api/v2/ai/operations/confirm` 只接收 `confirm_ref`。

确认入口重新检查当前会话、CSRF、限流、`ai_use`、原创建者、门店、白名单命令及 R3 政策，再交原总线恢复冻结参数。原业务权限、状态一致性、原子确认消费、幂等和同事务审计继续生效。拒绝任意 SQL、URL、低风险绕行、R4/R5 命令及 `notification.delivery_batch.enqueue`。生成手工清单不会发送短信；CSV 仅返回给本机操作员，不回灌模型。失败或连接中断的卡片不自动重试。

## 存储与预算

0074 扩展既有 AI 工具名称、有限事件卡、审计名称，以及用量异常的受限停用函数；不新增表，不放宽 RLS 或应用角色写权限。确认卡仍按原事件保留策略保存；审计只含工具名称、哈希、数量、结果和耗时，不含照片、顾客资料、命令参数或 nonce。模型调用继续使用既有预算、熔断、超时和工具次数限制；后续工具回合只使用剩余输出 token 额度。

供应商返回超出本轮额度、但仍在全局计量范围内的用量时，先按实际用量扣账，再结束本轮。已收到的用量终态超出全局计量范围或不为有效整数时，不按零用量释放余额：扣尽本轮预留额度，关闭会话，并在同一事务停用本组织 AI 配置、递增配置版本和记录 `ai.usage.quarantine`。此数值是保守预留扣款，不是已核实的供应商账单；管理员须核查外部账单并重新配置后才能恢复。

供应商明确返回生成上限时，保留已有用量并返回 `limit`，不执行任何截断的工具请求，不把图片结果视为有效分析。对应官方终止值为 [Anthropic `max_tokens`](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons)、[Gemini `MAX_TOKENS`](https://ai.google.dev/api/generate-content) 和 [DeepSeek `length`](https://api-docs.deepseek.com/api/create-chat-completion/)。

供应商调用已经开始但没有收到有效用量终态时，包括断流、取消、超时和输出保护提前终止，同样扣尽本轮预留并暂停配置。审计记为 `usage_unknown`，保留原失败或取消原因，不把用户取消记为超额度；已收到不合法用量记为 `outside_contract`。调用开始前的预算或权限拒绝不扣费用。隔离同一失败 turn 的重复处理不会再次停用管理员已恢复的配置。

## 验证边界

本批覆盖无业务副作用的 preview、冻结确认、重复确认幂等、越权/跨店/任意命令拒绝、模型上下文不含卡片、脱敏结果、结构化事件和真实 PostgreSQL admission/RLS。真实模型服务、Windows 安装形态与业务试点结果另行记录，不能由本地合成测试替代。

# ADR-80：Windows 程序与数据库结构联合升级、回退

- 日期：2026-10-03
- 状态：实现与软件回归完成，Windows 原生验收待完成
- 范围：ADR-72 A4；活动 V2 本机运行时，development_only

跨结构升级不再直接对正在服务的数据库执行迁移。操作先取得既有内核排他锁，完整验证来源和已安装发行，要求 PostgreSQL 版本一致，且新迁移清单严格追加于旧清单；任何历史 SQL、文件摘要或顺序变化都会在停止服务前拒绝。PostgreSQL 大版本/补丁版本迁移不在本协议内。

停止柜台服务后，以原发行验证当前库并创建数据库与两域照片的联合安全备份。创建带随机名称和 OID 身份的影子库，从可信快照恢复后校验旧迁移 ledger；随后使用新发行的迁移器升级影子库，再按新发行验证 ledger、关键表与照片引用。最后构建新发行的实际 HTTP runtime 和路由，执行内部健康请求。验证进程不开监听端口、不启动通知、打印或自动化 worker，使用单独受保护的照片副本，避免启动清理影响在线照片。

数据库切换使用同一事务中的双重重命名，随后以新发行重新验证，创建升级后联合快照，停止旧 PostgreSQL 进程，再持久化程序指针。只有写入 `verified` 阶段后，才删除旧库并恢复服务。程序指针、前后快照、候选库名称/OID、原状态均在受保护的 version 2 维护日志中绑定。

在 `verified` 之前中断，显式“继续中断维护”恢复原库与原程序；在该阶段写入成功但确认丢失后中断，则验证两份快照并完成已提交的新组合。恢复只操作日志绑定的数据库 OID，不能凭同名数据库推断归属。原始错误不进入操作界面；遇到未知布局保持停止，保留日志供明确恢复。

跨结构回退必须存在该新旧发行对的历史记录。系统先备份当前新结构数据，再恢复该次升级前的精确旧快照至影子库，并使用旧程序验证，然后联合选择旧程序与旧数据。升级后的业务写入保留在回退前安全备份中，不自动合并到旧结构。维护界面明确告知这一行为。相同结构版本继续沿用已有程序回退流程。

回退时，从当前库仅在内存读取显式允许的身份安全字段，在旧可信 schema 中覆盖匹配人员的密码/PIN、权限版本、启停和门店角色/隐私权限；当前已不存在的人员或角色禁用，不能复活旧权限。影子库内同一事务撤销所有会话、离线授权与租约，过期待执行 AI/导入/导出批准，暂停自动化并关闭短信配置。未完成短信转人工核对，保留费用、供应商回执摘要与接受时间，不自动重发；数据库回退不能撤销外部已发生的动作。维护审计与上述撤销同事务写入，重新登录、设备配对与再次批准后才恢复执行。正常向前升级不修改这些业务或身份状态。

普通同机备份恢复也必须应用相同身份覆盖与执行授权撤销。新的恢复日志在切换前持久化 `authority_reset: true`；历史记录已到 `verified` 但没有撤权证明时保持停止并明确拒绝自动完成，不把旧实现的提交状态当成安全证明。仅恢复到影子库后丢弃的演练不影响现有身份，换机恢复沿用 ADR-78 的独立重授权规则。

历史最多保留 15 个发行对，发行文件仍受既有 16 份限额约束；达到边界明确拒绝，不自动删除可回退资料。自动备份留存必须保护历史的前后快照和未完成维护日志引用。计划任务绑定独立的受验证留存维护发行，因此回退到较旧业务程序不会丢失维护入口。

回归覆盖影子创建、恢复、迁移、新程序验证、数据库切换、程序指针写入及 `verified` 确认丢失等中断点；另有实际 PostgreSQL 与 Windows 安装态联合升级/回退验收，结果分别记录，软件测试不能替代原生验收。本次不新增业务 Command/Query，不恢复 Cloud 或打印机工作。

# ADR-23：解冻催取工作台与人工通知名单

- 日期：2026-08-07
- 状态：**Accepted**
- 决策者：manpengan
- 前序：[ADR-16：边缘运营范围追认与契约面门禁](2026-07-31-adr-16-edge-operations-scope-ratification.md)
- 路线：[ADR-14：通用 V2 本地优先交付](2026-07-25-adr-14-generic-local-first-v2-delivery.md)
- 影响：`packages/contracts` v0.2 冻结面、`notification_log`、本地 Web 柜台

## 背景

ADR-16 §3 把“通知”整体留在后置阶段，但本地柜台仍缺一条不依赖外部平台的基本路径：
店员无法按超期天数找出已洗好、仍未取走的订单，也无法生成一份可在电话或现有聊天工具中
逐一联系的名单。直接接微信、短信或自动调度会引入账号、计费、模板审核、送达回执和隐私
留存等外部依赖，不适合作为当前 Linux 本地 Server/Web 的下一片交付。

本 ADR 只解冻“权威候选查询 + 人工名单生成”。它不是发送系统，也不得对外声称消息已发送。

## 决策

### 1. 契约面只新增一查一写

- R2 查询 `notification.pickup_reminders.list`：按当前会话注入的组织与门店读取催取候选；
- R3 命令 `notification.manual_list.create`：把用户明确勾选的 1–50 个当前候选生成 CSV，
  经过统一确认卡后执行并写入只追加记录。

v0.2 冻结面由 **34 → 35 条命令、20 → 21 条查询**。两项契约都拒绝离线执行，且不进入
只读 AI 投影。超过 50 单的批处理继续后置，避免跨入 R4 批量外联阈值。

### 2. 候选必须由服务端实时判定

候选限于当前门店 `open` 订单，且同时满足：

- 订单留有合法手机号；
- 订单创建时间至少达到用户选择的 30、90 或 180 天；
- 至少一件衣物当前为 `ready` 或 `racked`，并可按这两个状态过滤；
- 可选“仅欠款订单”；
- 结果最多 200 行，最早订单优先。

查询返回人工联系所必需的完整手机号，归类为 PII，权限沿用 `customer_read`。该号码不会进入
AI 工具投影。`last_contact_at` 只表示最近一次生成名单的时间，不表示联系成功。

### 3. 确认后再次锁定并复核

首次调用由通用 R3 策略生成冻结参数的 `confirm_ref`；确认续跑只提交该引用。执行事务内按
稳定顺序锁定所选订单，并以冻结的年龄、欠款和衣物状态条件重新查询。任一订单已取走、
已关闭、不再符合筛选或不属于当前门店时，整批拒绝，不输出部分名单。

名单可按订单或客户分组。模板只支持 `{{tickets}}`、`{{garment_count}}`、
`{{balance_cents}}` 三个占位符；服务端负责最终渲染。CSV 使用 UTF-8、RFC 4180 引号规则，
并防护电子表格公式注入；结果携带 SHA-256，Web 下载前复核摘要。

### 4. `notification_log` 是只追加的生成证据

新增组织级 RLS 表 `notification_log`，每个被选订单写一行，仍显式保存 `store_id` 并由所有
读写 SQL 过滤当前门店。固定语义：

- `channel = 'manual'`；
- `status = 'list_generated'`；
- `cost_cents = 0`；
- 保存批次、订单、可选客户、分组方式、消息摘要和导出摘要；
- **不保存**完整手机号、消息正文或 CSV。

业务行与审计行在同一命令事务提交。表仅授予应用角色 `SELECT, INSERT`，显式撤销更新、删除
和清空权限。

### 5. 产品文案不得夸大能力

Web 页面明确显示“短信/微信未接入”，主动作是“生成名单并复制号码”。完成态只能表述为
“名单已生成”，不得使用“已发送”“送达”或“通知成功”。剪贴板不可用时仍允许下载 CSV，
并向用户说明需要手动复制。

## 当前仍不做

- 微信、短信、电话网关或任何自动发送；
- 发送模板管理、计费、回执、失败重试与定时任务；
- 超过 50 单的批量操作；
- AI 生成话术或 AI 发起名单；
- 云端同步、多门店聚合、离线生成；
- macOS App 打包验收（本片只验 Linux 本地 Server + Web）。

## 后果

- ADR-16 §3 的“通知”后置项仅被本 ADR 的人工降级切片覆盖；真实渠道仍后置。
- `m2-freeze.test.ts` 必须同批点名新增的一查一写，PR 描述也必须声明冻结面变化。
- 完整手机号成为该页面的受权读取面，服务端权限、门店过滤和不进入 AI 投影均为硬门禁。
- 生成记录可用于避免重复联系和后续审计，但无法证明店员实际联系或顾客收到信息。

## 否决的备选

- **直接接短信或微信**：当前没有账号、模板审核、计费和回执边界，且扩大外部依赖，否决。
- **只在浏览器过滤现有订单列表**：无法权威判断衣物状态，也无法事务内复核与留审计，否决。
- **保存手机号与完整消息作为日志**：增加不必要的 PII 留存；摘要已足以证明导出一致性，否决。
- **生成即记为已发送**：人工步骤不可观测，会制造虚假的触达数据，否决。
